# Human claim review

Claim review is a separate workspace process under #23/#25/#36 and master #5. It does not change source rights, subscriptions, Agent admission, model findings or the draft status of a deliverable. `claim-review-1` records an assigned technical reviewer's actual assessment; the application checks their assigned role, workspace review permission, attestation and independence from the run author and cited source/document authors. It does not independently verify professional credentials or invent a human review.

## Operator and reviewer workflow

Assign a real qualified person the `technical_reviewer` role through the existing operator process and grant them owner/editor/reviewer membership in the specific workspace. Global reviewer status alone never exposes a private workspace. Real authentication and recent MFA apply to writes. No Agent subscription is required for reviewing retained output; current source permissions still apply.

1. Read `GET /api/v1/runs/{run_id}/claims/{claim_id}/review-packet`. This returns the exact current claim, evidence text, immutable locators/versions/hashes, extraction provenance, source notices, model/prompt identity and reviewed relationship snapshots, with a revision hash and current sequence. Only completed retained drafts are eligible. Reference-only or missing cited text cannot be assessed as evidence.
2. Perform the actual review outside model inference. Assess every cited passage as `supports`, `contradicts`, `context_only` or `unresolved`, with a reason. Examine exceptions, applicability, conflicting evidence and missing facts. The packet is a bounded retrieval selection, not proof of exhaustive research.
3. POST a `ClaimDecision` to `/api/v1/runs/{run_id}/claims/{claim_id}/reviews`, using the exact revision/sequence. Choose `supported`, `contradicted` or `unresolved`; provide competence/scope, private findings, a secure supporting-record handle/hash, an explicit future expiry and actual-review/competence/independence attestations. Supported requires at least one supporting passage and no contradictory or unresolved assessed passage; contradicted requires at least one contradictory passage. These schema checks cannot determine whether the reviewer is correct. Secure record handles are references, not file uploads or permission grants.
4. Reopen the packet to see a current decision. A changed claim/result, facts/context, evidence, source revision/permission, relationship review, reviewer role/membership or expiry invalidates it. A later assessment appends a new sequence. Reviewers cannot overwrite historical rows through this API.
5. `GET .../reviews` provides a paginated metadata-only history (50 records/page) and current status. It excludes historical findings and source bodies. To revoke after source access is withdrawn or a claim is removed, POST `decision: revoked`, an empty `passages` list, the latest `record_revision` and sequence from history, and the required actual revocation attestations. Revocation never needs to reacquire prohibited source text.

The API uses the same source-output accounting and final dependency checks as saved outputs. It locks the run before source release and serializes competing decisions; stale sequences fail instead of overwriting a review. The ledger stores claim hashes plus exact passage metadata/hashes, not additional copies of passage bodies. Review findings can themselves contain source text and are therefore only released for a current bound review under current output limits. Ledger records cascade when their run is deleted; deleting a reviewer nulls identity and invalidates the record. Existing job/parent-run retention constraints remain in force.

## Validation and remaining scope

Automated tests use fictional claims, mock runs and explicitly synthetic reviewer attestations. They are not professional approvals. PostgreSQL concurrency and migration tests run only in disposable local databases. Migration `0021_run_claim_reviews` adds one table and creates no historical approvals.

The API and machine-readable review packets are available now. A dedicated reviewer UI, packet export format, adjudicated claim-quality metrics, independently verified qualification administration and use of accepted human findings in downstream workflows remain follow-on work. No automatic professional approval, autonomous re-review, live notification or model call is introduced. Existing artifacts remain drafts even when an individual claim has a current supporting assessment.
