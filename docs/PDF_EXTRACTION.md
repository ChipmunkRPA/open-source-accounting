# PDF extraction coverage (#24)

Source intake and private uploads now use `pdf-text-pages-2`, a shared bounded text extractor. This is not a table reconstruction, image, OCR or professional-review service. It creates no rights grant. Source intake runs it in the existing isolated worker and preserves raw bytes on failure; a private upload is stored only after scanning and successful parsing.

Every physical page must yield non-whitespace text. A textless page rejects the entire extraction with `PDF_PARSE_BLOCKED`, `reason: page_without_extractable_text`, and its one-based `physical_page`. This includes legitimate blank separator pages: current handling requires operator reconciliation, not silent omission or automatic OCR. A mixed text/image-only document cannot appear fully extracted just because another page has text. No external OCR is invoked and no image is sent to a provider.

Each page records physical number/count, any declared PDF page label, a page-text hash and character count, parser and pypdf engine versions. Declared labels may be Roman numerals, prefixes or Arabic numbers; they are PDF metadata and are **not verified printed page numbers**. With no label dictionary, the label is null, rather than an inferred physical number. Source locators retain `PDF page N`; private locators retain `Page N` and chunk parts. Each private chunk retains its full-page text hash and zero-based, end-exclusive character range. These ranges refer to extracted text, not PDF byte offsets or visual coordinates.

Layout, tables, graphics and publication completeness explicitly remain unreviewed. A text-bearing page can still contain omitted images or incorrectly ordered table values; successful extraction does not prove those are captured. Review packets carry per-page metadata, and private document details expose it to authorized workspace readers. Agent deterministic inputs/results include document extraction limits; legacy PDFs without this metadata report unknown coverage. No existing document, source, normalized object or review is rewritten. Fresh source parses have separate version identities and still require independent review. Standalone SEC historical replay remains unchanged.

Limits: 16 MiB PDF input, 600 source-intake pages and 2,000,000 extracted source characters; private uploads use the existing upload limit, 150 pages and configured document-character limit. Worker input over its 12 MiB private bound is rejected rather than truncated. Existing CPU/process-memory/timeout bounds remain. Reachable PDF object dictionaries are bounded by depth and count; declared JavaScript/launch/remote actions, embedded attachments, XFA and rich-media structures are rejected, including page-annotation actions. Encryption, malformed/unsupported PDFs and limit violations also fail. This inspection complements malware scanning and isolation; it is not a complete PDF malware proof.

All new fixtures are original synthetic PDFs: labels, split-page ranges, textless/image-only pages, encryption, object actions, attachments, API failure rollback and separate source review. No real source, professional approval or human-adjudicated accounting case is added. Commands/results are in `reports/intake/PDF_EXTRACTION.md`.

Next: independent page-image/table review and supported format adapters, with exact review identity and operation permissions. DOCX currently extracts body paragraphs and then tables, which can lose their original interleaving; tracked revisions also need explicit handling before authoritative use. Continue all agreed content families under the same acquisition/rights/review gates.
