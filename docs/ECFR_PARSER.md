# eCFR intake parser version 2 (#8 / #24)

New `ecfr_xml` intake parses use `source-intake-ecfr-2`. Registration contracts and old manifest hashes are unchanged. A parse request for an artifact with an older extraction creates a separate version; idempotent retries reuse the new version. Existing normalized objects, staged sources and revision-bound reviews are not rewritten or transferred. The standalone SEC `sec-core-0.7.0` replay parser remains unchanged to verify historical snapshots. Its known header limitation is not approval to reuse old normalized text without review.

The new adapter preserves section headings, paragraphs, simple inline superscript/subscript and footnote-reference labels, footnotes, source notes, and both GPO and HTML-style XML tables. GPO `BOXHD/CHED` headers and `ROW/ENT` values remain in reading order with captions and notes. HTML table groups preserve header rows and individual row-header cell tags/attributes. Numeric signs, empty cells, and pipe characters remain explicit. Each passage includes its normalized hash, exact indexed XML path and printed-page observations. Structured tables retain row/cell paths and attributes. Local source-block numbering is not a fabricated legal subsection. Headings now receive their own passages, so later block numbers can differ from the old parser; use parser/extraction identity with locators.

Unknown elements, graphics, nested sections, duplicate section identities, complex fractions, nested tables, multirow/late headers, spans, unsupported layout attributes, uneven columns and mixed table-container text fail the complete extraction. Failure returns `ECFR_PARSE_BLOCKED` with a reason and XML path; raw bytes remain available under existing rights and nothing is partially staged. UTF-16 and non-UTF-8/ASCII declarations, DTD/entity declarations, malformed XML, excessive depth/elements/passages and oversized inputs are rejected. Existing subprocess CPU/memory/timeout limits still apply. No external resource is fetched by parsing.

The coverage is deliberately explicit: a successful parse is supported XML normalization, not an authenticity, completeness, historical-applicability or professional opinion. Annual CFR `CFRDOC` files must use the separate annual adapter. Effective dates are never inferred from page labels, headers or retrieval. Bibliographic families, images/OCR, complex formulas and all publisher vocabularies are not supported by this correction.

Operator sequence: acquire only with operation authorization, request the new parse, inspect exact old/new extraction hashes and raw paths in parser review, stage new versions, and obtain fresh independent technical/applicability review before indexing or Agent use. Old approvals do not migrate. Resolve unsupported structures against original artifacts, extend normalization under another parser version, and then reparse. Do not route failed files through older parsers to bypass failure.

`backend/tests/test_ecfr_parser.py` contains original synthetic fixtures: headers, numeric and empty cells, footnotes, paths, hashes, HTML table groups, unsafe/unsupported layouts and exact historical-extraction preservation with new-version retry. These are engineering tests; no actual regulation was acquired or professionally approved. Actual validation is in `reports/intake/ECFR_PARSER.md` and `progress.md`.
