# Annual CFR XML intake (#8 / #24)

The `annual_cfr_xml` adapter is version `source-intake-annual-cfr-1`. It preserves annual-volume identity independently of legal applicability and of the legacy `ecfr_xml` adapter. Existing manifest hashes and parser records remain valid. This is a supported-format adapter, not a claim that a full publisher volume has been acquired, validated against the XSD, or professionally reviewed.

Register via the intake API with `parser: annual_cfr_xml`, `annual_cfr: {year: 2025, volume: 3, revised_as_of: "2025-04-01"}`, `edition: "2025"`, `cfr_title: "17"`, XML MIME, family `FEDERAL_LAW` or `SEC_RULES`, and the exact official URL `https://www.govinfo.gov/bulkdata/CFR/2025/title-17/CFR-2025-title17-vol3.xml`. The revision date is optional and operator-declared; it is not a legal effective date. Preserve unresolved dates as null. No redirects or alternate hosts are accepted for this adapter. Registration grants no operations; existing acquisition, storage, extraction and review checks apply.

## Output and failure contract

- Each passage retains a hash, annual year/volume/title, declared revision date, observed XML headers, exact indexed XML path and printed-page markers. Printed page labels are observations, not physical PDF page numbers. Numeric header contradictions block parsing; missing/unrecognized headers remain visibly unverified.
- Supported `GPOTABLE` tables preserve one `BOXHD/CHED` header row, `ROW/ENT` cells (including empty cells, signs and formatting), captions, notes, row/cell paths and table/cell attributes. Simple inline superscripts, subscripts and footnote references are labeled explicitly. Raw bytes remain the authority for independent reconciliation.
- Multiple/spanning headers, unsupported cell alignment, inconsistent column counts, graphics, unsupported inline structures and unknown tags fail the entire parse. They are not silently omitted. The service returns `ANNUAL_CFR_PARSE_BLOCKED` with a reason and XML path, retains the raw artifact and creates no partial extraction or staged source.
- XML is bounded to the existing byte/CPU/process-memory limits plus 80 nested levels, 100,000 elements and 10,000 passages. Only UTF-8/ASCII declarations are supported; DTDs, entities, malformed XML and unexpected document roots are rejected. No external schema, image or entity is fetched during parsing.
- Parse and stage are separate. Normalized and staged passages remain unreviewed; annual metadata cannot grant rights, historical applicability, index approval or Agent admission. Parser-review packets retain the structured normalized output. A successful parse does not prove publisher completeness or that graphics were absent from the publisher's original.

The official [merged XML schema](https://www.govinfo.gov/bulkdata/CFR/resources/CFRMergedXML.xsd) informed vocabulary and table handling. The [publisher guide](https://www.govinfo.gov/bulkdata/CFR/resources/CFR-XML_User-Guide_v1.pdf) describes the annual format and its limitations; its 2009 date must not be confused with the directory modification date. Current legal authenticity requires separate verification. The legacy eCFR table path is unchanged and its header limitation remains open; do not route an annual publication through that adapter to avoid an explicit failure.
