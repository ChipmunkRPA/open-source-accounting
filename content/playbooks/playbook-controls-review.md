# Control design and deficiency review — Agent playbook

> **AI-assisted editorial draft — not professionally reviewed.** Original workflow guidance, not authoritative accounting advice. All scenarios are fictional. Confirm applicable authority, source permissions, and entity facts.

## Purpose and application status
This is an original procedure for the `controls_review` Agent workflow. The code catalogue currently marks it **experimental / deployment-gated**. Publication of this playbook does not establish that the workflow, source coverage, or accounting conclusions have been professionally validated. Reading this playbook is free; executing new Agent work in the hosted product requires the annual Agent subscription.

## Required intake
Risk, assertion, control narrative, owner, frequency, precision, evidence, actual operation history, known exceptions.

## Execution plan
Compare the control objective with the stated procedure. Determine what evidence would show the control operated and how exceptions are followed up. Separate design, implementation, and operating effectiveness. Analyze deficiency indicators by potential magnitude and likelihood, and consider other controls without assuming they compensate. Preserve the reporting-date assessment.

## Expected deliverable
Risk-control matrix; design questions; evidence gaps; deficiency-analysis worksheet; remediation plan and testing prerequisites.

## Stop or qualify the answer
Automatic severity classifications from a dollar threshold, or a claim that installing a new control proves effectiveness before operation.

## Reviewer handoff
Qualified reviewers assess likelihood, magnitude, aggregation, compensating-control precision, and communications. AI findings remain drafts.
