## A rounding example with a deliberately tiny total

For a separate mathematical exercise, allocate USD 0.01 across three equal positive weights in entered order A, B, C. Exact proportional shares are each one-third of a cent, so all cannot be displayed identically in whole cents while preserving the one-cent total.

The sample helper's stated policy floors proportional cent amounts and distributes leftover cents by largest fractional remainder, with equal remainders favoring later input rows. Under that policy, A receives 0.00, B 0.00 and C 0.01. This is an implementation rounding convention, not an accounting requirement or evidence that C is economically more important.

Reordering equal-weight rows can change which row receives the tie-breaking cent. Preserve input order and the policy. Do not quietly add a cent to an arbitrary line and claim the result follows from a unique exact allocation.

## Input validation is not accounting validation

The current arithmetic helper rejects negative numerical weights and a nonpositive total weight; a zero weight can receive zero when other weights are positive. Its acceptance of a value does not establish that zero is a valid standalone selling price for the actual accounting arrangement. Missing or unsupported inputs require resolution, not an invented estimate inserted to pass a validation check.

The transaction price is rounded to cents under the disclosed helper policy. Retain original accepted weight values without first reducing them to cents; that preserves the numerical ratios actually supplied. These controls address reproducible arithmetic, not recognition or scope.
